## 1. Данные уже собираются, нужна только проверка

### 1.1. Добавить проверки canonical: нет, несколько, разные, относительный адрес

- **Зачем:** ошибки canonical склеивают или выкидывают из индекса не те страницы.
- **Готово, когда:** на фикстуре 4 новые страницы попадают каждая в свою проверку: без canonical (замечание), два одинаковых canonical, два разных canonical (ошибка), canonical с относительным адресом.

- **Итог (2026-11-11):** сделано. 4 проверки в `Analysis.swift`; фикстура: `/canonical-none`, `/canonical-two-same`, `/canonical-two-diff`, `/canonical-relative`, остальные страницы получают canonical на себя.

### 1.2. Добавить проверки hreflang

Чек-лист:
- [ ] нет обратной ссылки со страницы-перевода;
- [ ] нет ссылки на саму себя;
- [ ] нет `x-default`;
- [ ] цель hreflang отвечает не 200;
- [ ] неверный код языка или региона (например, `ru-RUS`, `en-UK`).

- **Зачем:** на сайтах с языковыми версиями ошибки hreflang не видны руками.
- **Готово, когда:** на фикстуре пара страниц ru/en с намеренными ошибками даёт по одной странице в каждой из 5 проверок; правильная пара не попадает ни в одну.
- **Где:** `Analysis.swift`, поле `hreflang` в `Models.swift`.
- **Итог (2026-11-11):** сделано. Обходчик записывает hreflang связями (`LinkKind.hreflang`) и ставит цели в очередь; коды проверяются по спискам ISO из Foundation. Фикстура: `/hreflang/…`.

### 1.3. Добавить проверки перелинковки по графу ссылок

Чек-лист:
- [x] на страницу ведут только ссылки с nofollow;
- [x] на индексируемую страницу ссылаются только неиндексируемые страницы;
- [x] у страницы нет ни одной внутренней исходящей ссылки (тупик).

- **Зачем:** такие страницы получают мало веса, а в общих инструментах их не видно.
- **Готово, когда:** на фикстуре 3 новые страницы попадают каждая в свою проверку; страница `/about/` не попадает ни в одну.
- **Где:** `Analysis.swift`.
- **Итог (2026-11-12):** код, тест и фикстура готовы, окно не проверено. Фикстура: `/nofollow-only`, `/from-noindex`, `/dead-end`; в проверки попадают и старые `/deep1` (только nofollow с главной) и `/win1251` (ссылок нет). Проверки по входящим — только для индексируемых страниц в режиме «паук», как «мало входящих». Ссылка на себя тупик не отменяет. Важность — предложение из спецификации, ждёт подтверждения Петра.

### 1.4. Добавить проверки meta refresh и нестандартного Content-Type

- **Зачем:** meta refresh — редирект, который не виден по коду ответа; HTML с неверным Content-Type может не разобраться поисковиком.
- **Готово, когда:** страница с `<meta http-equiv="refresh" content="0; url=/about/">` попадает в проверку и показывает адрес перехода в инспекторе; HTML-страница с `Content-Type: text/plain` попадает во вторую проверку.
- **Где:** `Analysis.swift`, поле `metaRefresh`.

### 1.5. Добавить проверки sitemap: индексируемая страница не в sitemap, URL в нескольких sitemap

- **Зачем:** sitemap должен совпадать с тем, что сайт отдаёт в индекс.
- **Готово, когда:** при обходе фикстуры индексируемая страница вне sitemap попадает в первую проверку; URL, записанный в два файла sitemap, попадает во вторую, и в инспекторе видно оба файла.
- **Где:** `Sources/SEOparsCore/Sitemap.swift`, `Crawler.swift` (запоминать файл sitemap для URL), `Analysis.swift`.

### 2.4. Добавить проверки исходящих ссылок

Чек-лист:
- [ ] внутренних исходящих больше 1000 (порог в «Порогах»);

Чек-лист:

- [ ] двойной слэш в пути;

Кириллицу и заглавные буквы в адресе проблемой не считаем (см. разбор, раздел «Что не брать»).

### 2.7. Находить HTTP-страницы и смешанный контент на HTTPS

- **Зачем:** браузер блокирует ресурсы по HTTP на HTTPS-странице, ссылки на HTTP дают лишние редиректы.
- **Готово, когда:** внутренняя ссылка на `http://` при обходе `https://`-сайта попадает в первую проверку; страница, где `<img>`, `<script>` или `<link rel="stylesheet">` грузятся по `http://`, попадает во вторую с адресом ресурса. На фикстуре (она по HTTP) проверка покрыта юнит-тестом на HTML-строке.
- **Где:** `HTMLAnalyzer.swift` (собирать адреса ресурсов), `Analysis.swift`.

### 2.8. Находить ошибки разметки `<head>`

Чек-лист:
- [ ] недопустимый элемент в `<head>` (`<div>`, `<img>`, `<p>` и т. п.) раньше canonical или meta robots;
- [ ] несколько `<head>` или `<body>`;
- [ ] нет `<head>` или `<body>`.

- **Зачем:** браузер закрывает `<head>` на первом недопустимом элементе, и canonical или robots после него поисковик может не увидеть.
- **Готово, когда:** на фикстуре страница с `<img>` перед canonical попадает в первую проверку, и в инспекторе видно, какой тег прервал `<head>`; страница с двумя `<body>` — во вторую.
- **Где:** `HTMLAnalyzer.swift` (разбор по исходным тегам до SwiftSoup: SwiftSoup сам исправляет разметку и ошибку прячет), `Analysis.swift`.

### 2.9. Разделить проверки картинок: нет атрибута alt, пустой alt, длинный alt

- **Зачем:** пустой `alt=""` допустим для декоративных картинок, а отсутствие атрибута — ошибка. Сейчас это одна проверка.
- **Готово, когда:** на странице фикстуры с тремя картинками (без `alt`, с `alt=""`, с alt длиннее 100 символов) каждая попадает в свою проверку; пустой alt — замечание, без атрибута — предупреждение.
- **Где:** `HTMLAnalyzer.swift` (`imagesWithoutAlt`), `Analysis.swift`.
- **Итог (2026-11-11):** сделано. Порог `altMax` в «Порогах»; фикстура: `/images`.
