# SEOpars: SEO-парсер сайта для macOS (спецификация)

Дата: 2026-11-09, обновлено 2026-11-10 (п. 1.5 — пороги, п. 1.8 — проверки из разбора Screaming Frog). Статус: MVP собран 2026-11-09 (версия 0.1.0, см. README.md). Прогон на реальных сайтах делает Пётр.

## Рамки (согласовано 2026-11-09)

- **Объём:** стабильная работа до 5 000 страниц за обход. Больше — не цель MVP.
- **Экспорт:** только CSV. XLSX не нужен.
- **Интерфейс в реальном времени:** таблицы, счётчики и проблемы наполняются по ходу обхода, а не после завершения (п. 1.6).
- **Сборка:** для себя, на один Mac, без подписи и App Store.
- **Сравнение обходов:** решение за Петром, по умолчанию этап 2.

## Задача

Нативное macOS-приложение обходит сайт и собирает то, что SEO-специалист проверяет руками: H1, мета-теги, структуру заголовков и внутренние ссылки. Найденные проблемы показывает списком и выгружает в таблицу.

Аналог по смыслу: Screaming Frog SEO Spider. Отличие: заточка под Рунет и Яндекс, только нужные функции, без подписки и без лимита в 500 URL.

## Стек (по факту сборки MVP, 2026-11-09)

| Слой | Выбор | Итог проверки |
| --- | --- | --- |
| Язык и UI | Swift 6, SwiftUI, macOS 15+, пакет SwiftPM без Xcode | Собирается Command Line Tools. В SDK macOS 27 `@State` объявлен макросом, а плагина в CLT нет, поэтому сборка идёт с SDK 26.5 (`scripts/sdk.sh`) |
| Сеть | `URLSession` + свой планировщик на `async/await` | Пауза общая для всех потоков, редиректы не выполняются автоматически: каждый шаг записывается отдельно |
| Разбор HTML | SwiftSoup 2.14 (SPM) | Работает в режиме Swift 6: разбор идёт внутри функции, наружу выходят только Sendable-структуры |
| Хранилище | SQLite напрямую (системный `libsqlite3`), один файл на обход (`.seocrawl`) | GRDB не понадобился. Страница, её ссылки и очередь пишутся одной транзакцией. Продолжение после `kill -9` проверено |
| Таблицы | SwiftUI `Table` | 5 000 страниц и 425 тысяч ссылок: окно отвечает во время обхода, пик памяти около 430 МБ. Таблица держит объект на каждую строку, поэтому во вкладке «Ссылки» показываются первые 5 000 строк под фильтр, CSV выгружает все |
| Экспорт | CSV (UTF-8 с BOM, чтобы Excel открыл кириллицу) | — |

Один обход = один файл. Его можно закрыть, открыть, продолжить после паузы и позже сравнить с другим обходом.

## Этап 1 — MVP

### 1.1. Запуск обхода

- Стартовый URL. Режимы: «паук» (по ссылкам от стартовой) и «список URL» (вставить или загрузить .txt).
- Загрузка `sitemap.xml`, включая индексные sitemap. Нужна для поиска страниц-сирот (п. 1.4).
- Границы: только этот хост / с поддоменами / только подпапка. Лимит глубины и числа страниц.
- Фильтры URL: исключить и включить по регулярке (например, `/wp-admin/`, `?add-to-cart=`).
- Скорость: число потоков (по умолчанию 3), пауза между запросами. `Crawl-delay` из robots.txt учитывается.
- User-Agent: свой, Googlebot, YandexBot.
- robots.txt: учитывать или игнорировать (переключатель). Блок для выбранного бота разбирается отдельно.
- Кнопки «Старт», «Пауза», «Стоп», «Продолжить». Прогресс: обойдено, в очереди, ошибки, скорость (URL/с).

**Готово, когда:** обход двух реальных сайтов (WordPress + Elementor и Astro) проходит до конца, пауза и продолжение после перезапуска приложения не теряют и не дублируют URL.

### 1.2. Нормализация URL и кодировки (Рунет)

Без этого обход своих же сайтов даст дубли и «кракозябры», поэтому пункт входит в MVP.

- Кириллица в пути: `/каталог/` и `/%D0%BA%D0%B0.../` считаются одним URL. В таблице показывается читаемый вариант.
- Домены `.рф`: punycode внутри, кириллица в интерфейсе.
- Схема и хост приводятся к нижнему регистру, `#фрагмент` отбрасывается, порт по умолчанию убирается.
- Слэш на конце и регистр пути не склеиваются молча: это разные URL, и их дубль показывается как проблема.
- UTM и другие параметры: список «игнорировать параметры» (по умолчанию `utm_*`, `yclid`, `gclid`, `fbclid`).
- `Clean-param` из robots.txt (директива Яндекса) применяется при нормализации, если выбран YandexBot.
- Кодировка берётся из заголовка `Content-Type`, затем из `<meta charset>`, затем определяется по содержимому. windows-1251 и KOI8-R читаются правильно.

**Готово, когда:** на тестовом наборе (кириллические URL, `.рф`, страница в windows-1251, ссылки с utm) нет дублей и битого текста.

### 1.3. Данные по странице

**HTTP:** код ответа, цепочка редиректов (каждый шаг с кодом), `Content-Type`, время ответа, размер, `X-Robots-Tag`.

**Мета-теги:**
- `title`: текст, длина в символах, количество на странице.
- `meta description`: текст, длина.
- `meta keywords` (только показать, на ранжирование не влияет).
- `meta robots`, отдельно `meta name="googlebot"` и `meta name="yandex"`.
- `link rel="canonical"`: адрес, совпадает ли со страницей, какой код ответа у цели.
- `hreflang`, `html lang`, `viewport`.
- Open Graph (`og:title`, `og:description`, `og:image`) и Twitter Card.

**Индексируемость** — итоговый вывод в одну колонку: «индексируется» или причина, почему нет (код ≠ 200, noindex, canonical на другую страницу, запрет в robots.txt).

**Заголовки H1–H6:**
- Все заголовки по порядку с уровнем и текстом. В инспекторе — дерево.
- Счётчики: число H1, число заголовков каждого уровня.

**Контент:** число слов в видимом тексте, хеш текста (поиск полных дублей), число картинок, картинки без `alt`.

**Готово, когда:** для любой страницы обхода инспектор показывает все поля выше, а значения совпадают с исходным кодом страницы при ручной проверке 10 случайных URL.

### 1.4. Внутренние ссылки

Здесь своя программа выигрывает у общих инструментов, поэтому раздел подробный.

**Таблица связей** (одна строка — одна ссылка):
- источник, цель, анкор (для картинки-ссылки — её `alt`), `rel` (`nofollow`, `sponsored`, `ugc`);
- тип: `<a>`, canonical, редирект, `<img>`, hreflang (с 2026-11-11, № 101);
- зона на странице: меню, шапка, подвал, контент. Сначала свои правила «зона ← CSS-селектор» из настроек обхода (с 2026-11-11, № 115), затем эвристика по разметке (`<nav>`, `<header>`, `<footer>`, `<main>`, `<aside>`), на сайтах без семантической вёрстки будет ошибаться — это помечено в интерфейсе.

**По каждой странице:**
- входящие и исходящие ссылки списком с анкорами (вкладки в инспекторе);
- число входящих: всего и с уникальных страниц;
- глубина — сколько кликов от главной по кратчайшему пути;
- распределение анкоров на эту страницу (какими словами на неё ссылаются).

**Проблемы со ссылками:**
- битые внутренние ссылки (цель 4xx/5xx) с указанием, где стоит ссылка;
- ссылки на редирект (надо менять на конечный адрес);
- `nofollow` на внутренних ссылках;
- страницы-сироты: есть в sitemap, но ни одной входящей ссылки;
- страницы глубже заданного уровня (по умолчанию 3);
- страницы с одной-двумя входящими ссылками.

**Готово, когда:** на обходе реального сайта можно выбрать любую страницу и увидеть, кто на неё ссылается и с какими анкорами; список битых ссылок совпадает с ручной проверкой трёх заведомо битых ссылок.

### 1.5. Проверки (вкладка «Проблемы»)

Каждая проверка — строка: название, важность (ошибка / предупреждение / замечание), число затронутых страниц. Клик открывает список URL.

| Группа | Проверки |
| --- | --- |
| Title | нет, пустой, дубль, короче/длиннее порога, несколько на странице |
| Description | нет, пустой, дубль, короче/длиннее порога |
| H1 | нет, несколько, пустой, дубль между страницами, совпадает с title |
| Заголовки | пропуск уровня (H2 → H4), пустые заголовки, H2–H6 до H1 |
| Ответы | 3xx, 4xx, 5xx, цепочки из 2+ редиректов, долгий ответ |
| Индексация | noindex, canonical на другой URL, canonical на не-200, неиндексируемая страница в sitemap |
| Ссылки | всё из п. 1.4 |
| Контент | полные дубли по хешу, мало слов, картинки без атрибута alt, с пустым alt, с alt длиннее порога |

**Пороги длины title и description — предположение.** По умолчанию 30–65 символов для title и 70–160 для description. Это рабочие ориентиры, а не официальные нормы Яндекса или Google, поэтому все пороги настраиваются.

**Решение по порогам (Пётр, 2026-11-10):**
- title 30–65 и description 70–160 остаются. В Screaming Frog 18.4 стоят 30–60 и 70–155, но они подобраны под ширину сниппета Google, а нормы Яндекса нет.
- «Мало слов» — меньше **200** слов, как в Screaming Frog 18.4 (было меньше 100). Пока не сделана область контента (п. 1.8, № 114), в счёт входят меню и подвал, поэтому порог перепроверить на прогоне реального сайта.

Проверки из разбора Screaming Frog, принятые поверх этого списка, — в п. 1.8. Проверка «картинки без alt» 2026-11-11 разделена на три (№ 113).

**Ограничение:** без отрисовки CSS и JS приложение не видит, скрыт ли заголовок или текст стилями.

### 1.6. Интерфейс

- **Боковая панель:** сохранённые обходы.
- **Верх:** строка URL, кнопки управления, прогресс.
- **Вкладки:** Обзор (сводка: коды ответов, индексируемость, топ проблем) · Страницы · Мета-теги · Заголовки · Ссылки · Редиректы · Проблемы.
- **Таблицы:** сортировка по колонкам, поиск, фильтры («только 200», «только индексируемые», «H1 отсутствует»), скрытие и порядок колонок.
- **Инспектор снизу** для выбранного URL: сводка, дерево заголовков, входящие, исходящие, HTTP-заголовки, исходный код.
- Действия по строке: открыть в браузере, скопировать URL, перейти к источнику ссылки.

**Обновление в реальном времени:**
- Каждая обойдённая страница сразу появляется в таблицах «Страницы», «Мета-теги», «Заголовки», «Ссылки».
- Счётчики сверху (обойдено, в очереди, коды 2xx/3xx/4xx/5xx, URL/с) и вкладка «Проблемы» пересчитываются по ходу.
- Обновления идут пачками примерно раз в полсекунды, чтобы интерфейс не дёргался от каждой страницы.
- Сортировка, фильтр и выбранная строка сохраняются, пока данные добавляются.
- Проверки, которым нужен весь сайт (сироты, дубли, глубина, число входящих), во время обхода показывают промежуточный результат с пометкой «обход не завершён» и окончательно пересчитываются после остановки.

**Готово, когда:** на обходе 5 000 страниц таблица прокручивается и сортируется без заметных подвисаний во время обхода, а инспектор открывает страницу, обойдённую секунду назад.

### 1.7. Экспорт

- Любая таблица или отфильтрованный список → CSV (UTF-8 с BOM, разделитель — точка с запятой или запятая на выбор).
- Отдельный экспорт таблицы связей (источник → цель → анкор) для анализа перелинковки в Excel или Google Sheets.

**Готово, когда:** CSV с кириллицей открывается в Excel и Numbers без ручной смены кодировки.

## Этап 2

- **Сравнение двух обходов:** новые 404, изменившиеся title, description и H1, пропавшие страницы, новые редиректы. Полезно после релизов и миграций. Поля, статусы URL и сопоставление адресов после миграции распишет задача № 120 (TASKS-SF, п. 5.1).
- **Внутренний PageRank:** вес каждой страницы по графу ссылок. Показывает, куда утекает вес и какие важные страницы недополучают ссылок.
- **Граф перелинковки:** визуализация (силовая раскладка) с подсветкой разделов и сирот.
- **Генерация sitemap.xml** из индексируемых страниц.
- **Структурированные данные:** типы schema.org из JSON-LD и microdata, базовая проверка обязательных полей.
- **Пользовательское извлечение:** CSS-селектор или регулярка → своя колонка (цена, артикул, наличие счётчика).
- HTML-отчёт для клиента.
- **Basic Auth** для закрытых стендов. Пароль хранится в Связке ключей.

## Этап 3

- **Отрисовка JS** через `WKWebView` для SPA. Для текущих сайтов не нужна: WordPress + Elementor и Astro отдают готовый HTML с сервера (это вывод из стека сайтов, на каждом сайте стоит проверить сравнением исходного и отрисованного HTML).
- Обход по расписанию и уведомление о новых ошибках.
- Данные Яндекс Вебмастера и Google Search Console рядом с данными обхода.
