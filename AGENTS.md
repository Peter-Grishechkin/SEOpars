# Правила для агентов

SEOpars — нативный SEO-парсер сайта для macOS (SwiftUI + SwiftPM, без Xcode). Начинать с `README.md`, затем `SPEC-2026-11-09.md` (функции и критерии готовности). Дата правил: 2026-11-09.

## Сборка и тесты

- Собирать только `./scripts/build-app.sh`, тестировать только `./scripts/test.sh`. Голые `swift build` и `swift test` под Command Line Tools не работают: `scripts/sdk.sh` подставляет SDK macOS 26.x (в SDK 27 `@State` — макрос, а плагина SwiftUI-макросов в CLT нет), `test.sh` передаёт путь к плагину Swift Testing.
- Если установлен Xcode, `sdk.sh` ничего не подменяет. После установки Xcode проверить сборку без обхода и убрать пометку из `README.md`.
- Версия живёт в `scripts/build-app.sh` (`VERSION`). При смене версии обновить бейдж версии в `README.md` и запись в `CHANGES-LOG.md`.
- Картинки README (`docs/images`) — снимки настоящего приложения, пересобираются `./scripts/render-screenshots.sh` после заметных изменений интерфейса. Скрипту нужен экран на 1–2 минуты: запускать, когда Пётр согласен не трогать мышь и клавиатуру.
- Сборка идёт в `build/` (приложение и `seopars-cli`), эта папка в Git не попадает.

## Проверка поведения

- Тестовый сайт: `python3 -I Tests/Fixtures/fixture_server.py 18990`. Запускать с `-I`.
- Критерии «Готово, когда» из спецификации проверять на реальных сайтах вместе с Петром (какие сайты — знает Пётр, в репозиторий их не записывать): прогон на них делает он, пока не сказано иначе.
- Не обещать «работает» по одной сборке: указывать, что именно запущено (тесты, фикстура, реальный сайт).

## Данные

- Обходы лежат в `~/Library/Application Support/SEOpars/Crawls/` (`*.seocrawl`, SQLite). Не удалять и не править файлы там без запроса Петра: в них результаты прошлых обходов.
- Файлы `*.seocrawl` и выгрузки CSV с чужих сайтов в Git не попадают.
- Паролей, ключей и токенов в коде и файлах проекта нет. Для Basic Auth (этап 2) пароль хранить в Связке ключей.

## Код

- Ядро без интерфейса — `Sources/SEOparsCore`, интерфейс — `Sources/SEOpars`, CLI — `Sources/seopars-cli`. Логику обхода и проверок добавлять в ядро с тестом в `Tests/SEOparsCoreTests`, а не во вью.
- Swift 6: из разбора HTML наружу выходят только `Sendable`-структуры.
- Пороги длины title и description — рабочие ориентиры, а не нормы Яндекса или Google. Так и называть в интерфейсе и тексте.
- Нормализация URL: слэш на конце и регистр пути не склеивать молча (п. 1.2 спецификации).

## Git

- `origin` — публичный репозиторий https://github.com/Peter-Grishechkin/SEOpars: открыт 2026-11-11 по просьбе Петра: история сжата в один коммит, репозиторий пересоздан, чтобы GitHub не отдавал старые коммиты по SHA. Ветку `backup/pre-public-2026-11-11` не пушить, SHA из неё в файлы не писать. Не пушить, не менять `remote` и видимость репозитория и не коммитить без запроса Петра.
- Репозиторий публичный: имена клиентских сайтов, их адреса и выгрузки в файлы проекта не писать, в тексте — «реальный сайт».
- Перед Git-операциями проверить папку, ветку (сейчас `master`) и незакоммиченные изменения.

## Документация

- Новые проверенные факты (замеры, результаты прогонов на сайтах) писать с датой и пометкой «проверено» / «не проверено».
- Каждое изменение проекта — строкой в `CHANGES-LOG.md`: дата, что сделано, файлы, как проверено.
