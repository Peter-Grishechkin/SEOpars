# Что взять из Screaming Frog в SEOpars

Дата: 2026-11-09. Сравнение с `SPEC-2026-11-09.md` и кодом SEOpars 0.1.0.

## Откуда данные

- Установлен Screaming Frog SEO Spider **18.4** (`/Applications/Screaming Frog SEO Spider.app`). Программа сообщает, что есть версия 25.1, её я не смотрел: список ниже может быть неполным для свежих версий.
- Источники внутри приложения: файл строк интерфейса `translations/SeoSpider_en.properties` (каталог проверок, колонки, отчёты, настройки) и классы настроек из `ScreamingFrogSEOSpider.jar` (значения по умолчанию, прочитаны через `javap`). **Проверено** по этим файлам.
- В самом Screaming Frog ничего не запускал. На реальных сайтах ничего не проверял.
- Тексты описаний и советов SF сюда не копировал: формулировки свои.
- Пометка «предположение» — мои выводы для Рунета, они не взяты из SF.

Список «неинформативных анкоров» в SF только английский: click here, here, more, read more, learn more и подобные.

## Уровень 1. Данные уже собираются, не хватает только проверки

Самое дешёвое: разбор есть в `HTMLInfo`, но в `Analysis.swift` проверок нет (проверено поиском по коду).

| Что добавить | Что уже есть | Основание |
| --- | --- | --- |
| Meta refresh (редирект на стороне клиента) | `metaRefresh` разбирается | SF: `redirection_meta` |
| Hreflang: нет обратной ссылки, нет ссылки на себя, нет x-default, цель не 200, неверный код языка | `hreflang[]` разбирается | SF: группа `hreflang_*` |
| Canonical: нет, несколько, несколько разных, относительный адрес | `canonicals[]` | SF: `missing_canonical`, `multiple_canonical`, `multiple_conflicting_canonical`, `canonical_is_relative` |
| На страницу ведут только nofollow-ссылки | флаги `rel` у ссылок | SF: `internal.nofollow.inlinks.only` |
| Индексируемая страница, на которую ссылаются только неиндексируемые | индексируемость и граф ссылок | SF: `non_indexable_page_inlinks_only` |
| Индексируемая страница не в sitemap; URL в нескольких sitemap | sitemap загружается | SF: `urls_not_in_sitemap`, `urls_in_multiple_sitemaps` |
| Страница без внутренних исходящих ссылок (тупик) | граф ссылок | SF: `no.internal.outlinks` |

X-Robots-Tag с noindex в SEOpars уже учитывается в индексируемости (`Analysis.swift:506`), добавлять не нужно.

## Уровень 3. Уже есть в этапе 2 спецификации — что подсмотреть

- **Сравнение обходов.** В SF разделение на «новые», «добавленные в фильтр», «удалённые», «пропавшие» для каждой проверки, плюс отслеживание изменений по полям: глубина, число слов, title, H1, description, индексируемость, входящие (всего и уникальные), исходящие, типы структурированных данных. Есть сопоставление URL регуляркой — нужно после миграции. Этот список полей можно взять как готовый чек-лист.
- **Внутренний PageRank.** В SF это Link Score (0–100) и колонка «% от всех» по уникальным входящим.
- **Граф перелинковки.** В SF три вида: силовая раскладка, дерево по папкам и по кратчайшему пути, облако анкоров на страницу. Облако анкоров — дёшево и полезно для п. 1.4.
- **Пользовательское извлечение и поиск.** SF ищет текст или регулярку с режимами «содержит / не содержит» в HTML, тексте и тексте без анкоров. Пример применения: найти страницы без счётчика Метрики.
- **Структурированные данные.** SF проверяет по словарю schema.org и правилам Google. Для Рунета правил Google мало (**предположение**): Яндекс поддерживает свой набор, его надо описать отдельно.

## Что взять в настройки и интерфейс

- **Область контента** для подсчёта слов и дублей: включить или исключить теги, классы и id (например, `nav`, `header`, `footer`, `.elementor-location-header`). Без этого на шаблонных сайтах меню и подвал раздувают число слов и мешают искать дубли (**предположение**, проверить на реальном сайте).
- **Свои правила зон ссылок** поверх текущей эвристики, с полем «проверить путь». Спецификация сама отмечает, что эвристика ошибается на вёрстке без семантических тегов.
- **Переписывание URL**: удалить параметры, замена по регулярке, привести найденные URL к нижнему регистру. Список игнорируемых параметров в SEOpars уже есть, регулярки нет.
- **Почти дубли** (сходство текста от 90 %), с опцией «только индексируемые». Полные дубли по хешу у нас есть.
- **Три типа проблем**: ошибка, предупреждение, возможность для улучшения, плюс приоритет (высокий, средний, низкий). У каждой проверки поле «как исправить» своими словами.
- **Отчёты, которых нет**: цепочки редиректов и canonical одной таблицей, сироты, небезопасный контент, сводка по проблемам для клиента.
- **Пакетная выгрузка**: все анкоры, все входящие картинки, заголовки ответов, исходники страниц.

## Что не брать для Рунета

- **Кириллица и не-ASCII в URL как проблема** (SF: `non_ascii_characters`). В Рунете это норма, у нас кириллические URL нормализуются (п. 1.2).
- **Заглавные буквы в URL как отдельная проблема** (SF: `uppercase`). У нас регистр уже ловится как дубль URL (`urlVariantDuplicate`).
- **Ширина сниппета в пикселях.** Настроена под шрифт выдачи Google, к Яндексу не подходит (**предположение**).
- **Директивы `noodp` и `noydir`.** Устарели.
- **AMP, старая AJAX-схема (`_escaped_fragment_`), PageSpeed, GA и GSC, проверка орфографии.** Вне рамок спецификации или устарело. Данные Вебмастера и GSC уже стоят в этапе 3.
- **Заголовки безопасности (HSTS, CSP, X-Frame-Options и другие).** Это не SEO, пусть остаются на усмотрение Петра.

## Предложение по порядку

1. Уровень 1 целиком: данные уже есть, нужны только проверки и тесты в `Tests/SEOparsCoreTests`.
2. Из уровня 2: строка robots.txt, H2, анкоры (пустые и неинформативные русские), ошибки `<head>`, якоря `#id`, URL-проблемы.
3. Область контента и свои правила зон ссылок — до прогона на реальном сайте, иначе число слов и зоны будут неточными.
4. Сравнение обходов (этап 2) — по чек-листу полей из SF.

Изменения в спецификацию не вносил: это решение за Петром.
